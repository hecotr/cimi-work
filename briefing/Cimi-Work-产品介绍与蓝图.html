执行机制讲法，约 2 分钟

逐一点击四种机制。通用 Team 可以组合分工；Matrix AgentTeams 需要独立接入；业务 Harness 可以主导整项工作，并定义自己的阶段和门禁。首版先打通单 Agent 和固定协作路径，模型支持四类机制不代表四套引擎都已建成。

技术边界讲法，约 2 分钟

沿四层往下讲。Task Runtime 负责持续工作，不另造一套模型执行循环；路由负责新建或续接，不替代 Harness 内部流程。切换三种输入：明确委托直接进入正常流程，相关反馈回到原 Task，主动候选默认观察。旧 Run 的迟到回调不能覆盖当前有效状态，重复事件不能造成重复动作。

先跑通云端交付，再验证跨端协作

首版优先云端真实交付，下一阶段验证专业流程与本地协作。路线属于 PRD 的实施建议，具体范围、资源能力和排期需在接入评审后确认。

  1. 首版，云端真实闭环

    两类空间、我的工作、目标式创建、上下文、固定协作、人工待办、交付与验收。

  2. 下一阶段，专业与跨端接入

    Harness 阶段与回退、本地 Agent 真实协作、主动事件接单。

  3. 后续增强，扩展协作能力

    动态组队、更多连接器、定时触发、成本与并发策略、知识回流。

用一条真实任务验收首版

只填目标发起工作，Agent 使用获准资料，必要时请求人参与，最终交付可打开的产物与有效验收记录。

重点检查：执行真实发生，通知状态可核对，中断后可恢复。

路线讲法，约 2 分钟

先用云端分析与报送验证真实闭环，再讨论扩展。四种机制统一建模，不意味着首版同时自建四套引擎。本地协作是明确产品目标，连接和恢复协议还要验证。路线不写未经确认的日期，不把原型演示当成实际接入已完成。

收尾讲法，约 1 分钟

回到一次真实任务能否从目标走到有效验收。用左侧清单汇总已对齐内容，再讨论右侧三类问题：可用执行资源、共同事实与协议、验收和跨端边界。最后约定首条真实闭环的业务场景与负责人，排期依据资源核实后再定。
