# Cimi Work 交互原型

按 `docs/Cimi-Work-PRD.md` 第 12 节制作的中文高保真原型。采用 Hallmark Console 的 paper 浅色工作台方向，首页为“我的工作”。

## 本地运行

无需安装应用依赖，使用 Node.js 运行：

```powershell
node prototype/server.mjs
```

打开终端输出的 `http://127.0.0.1:4173`。静态应用位于 `dist/`，可直接部署。数据只保存在当前浏览器的 localStorage；页脚可重置演示数据。所有 Agent、成员、文件、回复、通知和执行过程均为演示，没有接入真实账号或 Agent。

## 建议体验顺序

1. 从“我的工作”处理 CW-1042 的收入口径确认，点击“推进演示”查看分析成果、模拟通知回执与人工验收；验收后可提出修改，保留历史版本。
2. 打开 CW-1038，切换专业阶段视图，体验 N2 回退到 N1、确认后创建新 Run，再推进 N3–N5 与交付验收。
3. 进入个人空间的 CW-1035，选择目标或成果发布到项目。原私有 Task 保留；未选择的目标、私有资料和讨论不随发布进入项目。
4. 新建任务时选择 Agent、通用 Team、Matrix AgentTeams 或业务 Harness；尝试空间默认匹配、项目创建、成员与资源配置。
5. 在任务中邀请已授权 Agent，或为人添加明确的非阻塞协作事项并记录模拟答复。

## 实现边界

这是可点击的前端原型。任务推进、上下文查找记录、回退恢复、权限说明和自动验收均为本地规则模拟，不能据此推断真实多用户隔离、Agent 调度或云端状态同步已经实现。本地 Agent 入口显示为下一阶段能力。

默认人工验收。空间设置显式启用自动验收后，仅在演示成果产生时应用规则。尚未覆盖生产级 Harness 验收规则编辑、真实连接器、授权握手及运行时故障恢复。

## 验证记录

2026-11-02：独立 Chrome 无头浏览器通过 19 个交互场景，无脚本错误。覆盖目标校验、四类执行方式、决策恢复、成果版本与验收、Harness 回退、选择性发布、自动验收、新项目与成员、搜索、页面状态、取消与恢复、持久化、键盘弹窗、空间提示和人的协作待办。

在 320、375、768、1280、1440、1920 像素宽度检查首页、任务、创建页和资源页，未发现页面级横向溢出。Hallmark 对首页、任务、创建页、资源页执行渲染检查：Floor 0、Reflex 0、未处理警告 0；F4 将中性按钮判作主按钮，已核对并作出说明。视觉检查在本线程完成，使用原型快速流程。

浏览器测试工具不随应用分发：

```powershell
npm install --prefix prototype/qa-deps --no-save puppeteer-core
node prototype/qa/verify.mjs
```

如 Chrome 不在默认路径，设置 `CHROME_PATH`；如预览端口不同，设置 `CIMI_PREVIEW_URL`。`qa/` 的测试脚本可重复运行，生成结果和截图会被 Git 忽略。

## 交付方式

按用户确认，仅保留本地原型，没有上传源码或发布在线预览。运行本地服务即可体验，停止服务后再次运行上述命令可恢复访问；浏览器中的演示记录仍会保留。
